# Карта контекста Sikkerheit

Типовые задачи и минимальный набор файлов для каждой. Состояние на 2026-10-13, пакет 0.2.0. Пути даны от `development-package/`, если не указано иное. Правила работы — в [AGENTS.md](../AGENTS.md); стадии, гейты и статус — в [WORKFLOW.md](WORKFLOW.md).

## Задачи

### Продукт, этапы, объём

`README.md` → «Приоритет документов», затем `01`. Решения и риски — `08`; выбор A/B — `07` → «SP-05: выбор источника Windows-фактов», `02` → «Вариант B: импорт без агента».

### Изменить или добавить Windows-проверку

- Читать: `03` → «Семантика результата», «Проверки Windows»; `contract_catalog.py` (`CHECKS`), `contract_schemas.py` (evidence), `generate_contracts.py` (`SYNTHETIC_EVIDENCE`).
- Обновить вместе: строку в таблице Windows `03` (колонки «Объект», «Режим по умолчанию» сверяются с каталогом); параметры политики — `05` → «Политика клиента» и PolicyConfiguration; переходы — `05` → «Состояния проблем»; приёмку — `07` (AT-03, AT-05, AT-06); инварианты — `invariants_data.py`.
- Число WIN-проверок вычисляется (`maxItems = len(AGENT_IDS)`), литералов нет.

### Проверки Microsoft 365 и права Graph

- Читать: `03` → «Проверки Microsoft 365», «Возможности интеграции»; `04` → «Разрешения интеграций»; `02` → «Выполнение облачной проверки».
- Обновить вместе: `10-sources.md`; `08` (ADR-06, ADR-10, R-06, R-14); `07` (SP-03, WP-08, AT-09…11, AT-15); P2-записи в `invariants_data.py`.
- P2-операций в OpenAPI нет; M365-проверки есть только в каталоге.

### Пакет агента, evidence, приём пакета

- Читать: `05` → «API агента» (порядок приёма, окна, время и часы, Problem.code, автомат агента), «Канонический объект и идентичность устройства»; `contract_schemas.py`.
- Обновить вместе: отрицательные варианты — `validate_contracts.py` (`_negatives`); инварианты — `invariants_data.py`.

### HTTP API агента или портала

- Читать: `05` → «API агента», «API портала»; `contract_paths.py` (операции, security, наборы ответов, заголовки); роли и `x-audit-read` — `contract_catalog.py`.
- Обновить вместе: таблицы операций в `05` (каждый operationId в колонке `operationId`); таблицу Problem в `05`; роли — `04` → «Вход в портал и роли»; FR — колонка «Контракт» в `01`; проверки — `validate_contracts.check_openapi`.
- Сам `openapi.json` смотреть через `jq` (команды в конце).

### Состояния проблем, история, отчёт, покрытие

`05` → «Состояния проблем» (таблица eventType × cause, таблица переходов, workflowState), «Отчёт и покрытие»; `03` → «Семантика результата»; `01` → «Язык портала и отчёта»; `07` → AT-05…08.

### Регистрация агента, сертификаты, mTLS, отзыв

`04` → «Регистрация и сертификаты агента» (enrollment-токены, профиль и продление, доверие ingress и XFCC, граница ключа CA); `05` → «API агента», «Канонический объект и идентичность устройства»; `07` → SP-02, AT-02, AT-17; `08` → ADR-05.

### Изоляция клиентов, роли, RLS, аудит

`02` → «Разделение клиентов»; `04` → «Вход в портал и роли», «Угрозы и проверяемые меры»; `05` → «Сущности и ограничения»; `07` → SP-04, AT-01.

### Персональные данные, сроки хранения, удаление

`04` → «Минимизация данных» (таблица сроков); `05` → «Жизненный цикл организации»; `06` → «Восстановление и удаление», «Журнал жизненного цикла и restore в карантине»; `01` → «Границы обещаний».

### Azure, выпуск агента, эксплуатация, расходы

`06`; `08` → ADR-04, ADR-05, ADR-07; `07` → WP-07a, WP-07b, AT-12…14, «Runbooks».

### План, трудоёмкость, приёмка

`07`. Связь FR → AT и операции — таблица в `01` → «Функциональные требования».

### Независимое ревью

Порядок запуска — [WORKFLOW.md](WORKFLOW.md) → «Ревью G0» и «Реестр сессий ревьюеров»: рецензенты стартуют и возобновляются только через `reviewer-cli` на снимках пакета. Запрос рецензентам — `09` → «Текст запроса»; `REVIEW-BUNDLE.md` и ZIP самим читать не нужно.

### Выпуск новой версии пакета

- Версия: `build_package.py` (`VERSION`, `DATE`; дата в заголовке `REVIEW-BUNDLE.md` берётся из `DATE`), `contract_catalog.py` (`CATALOG_VERSION`), `README.md` (строка 3), `09` (строка 3); validate сверяет их совпадение. Имя ZIP строится из `VERSION`; старые архивы остаются в корне.
- `10-sources.md`: колонка «Сверено» — по каждой строке отдельно.
- Журнал принятых и отклонённых замечаний — вне пакета, `docs/reviews/`.

### Начало реализации P1

`02` → «Компоненты», «Структура будущего репозитория»; `07` → «Правила P0 и старт P1», «Эксперименты P0», «Backlog и зависимости»; `08` → «Архитектурные решения». Кода пока нет; когда появится, добавить сюда разделы по коду.

### Журналы и отчёты (вне пакета)

`reviews/G0-r1-journal.md` (путь от `docs/`) — журнал решений по ревью G0 v0.1.0: сводная таблица кластеров в начале, решения — `### C-NN · …`, поправки критика внутри кластеров, решения владельца и вопросы в конце. Нужный кластер искать через `rg -n '^### C-15'`.

`reports/2026-10-13-readiness-audit.md` (путь от `docs/`) — аудит готовности пакета v0.1.0: 94 замечания с доказательствами, в конце дополнение о составе Windows-лаборатории. Заголовки замечаний `### <ID> · <severity>`.

## Форматы, которые читает validate

Менять заголовки и первые ячейки только вместе с `validate_docs.py` и `doc_tables.py`.

| Файл | Что ищется |
| --- | --- |
| `01` | Таблица `| ID | Требование | Этап | Приёмка | Контракт |`, строки `| FR-nn |`, ровно FR-01…13 |
| `03` | Таблица с колонками `ID`, `Объект`, `Режим по умолчанию`: строка `| WIN-xxx |` / `| SYS-xxx |` на каждую проверку каталога, значения без обратных кавычек |
| `04` | Таблица `| Роль | Область | Разрешения |` со строкой `| PlatformAdmin | платформа |` |
| `05` | Таблицы операций с колонкой `operationId` (все 34); `| code | HTTP | Операции | Когда | Действие агента |` (HTTP числом, совпадает с каталогом); `| eventType | Допустимые cause | assessmentId |` (cause через «, », как `EVENT_TABLE`) |
| `07` | Строки `| AT-nn |` (ровно 17), `| RB-nn |` (ровно 14), `| SP-nn |`, `| WP-nn |` |
| `08` | Строки `| ADR-nn |`, `| R-nn |` |
| Все `.md` | Каждый упомянутый FR/AT/RB/SP/WP/ADR/R/INV определён в своём файле; локальные ссылки разрешаются; заголовки, на которые ссылается `invariants.json` (`sourceDoc`), существуют |

## Не читать целиком

| Файл | Размер | Вместо этого |
| --- | --- | --- |
| `REVIEW-BUNDLE.md` | ~760 КБ, ~14 800 строк | Исходные файлы пакета |
| `specs/openapi.json` | ~10 200 строк | `contract_paths.py`, `contract_schemas.py` или `jq` |
| `specs/invariants.json` | ~1 400 строк | `invariants_data.py` или `jq` |
| `specs/observation.schema.json` | ~1 200 строк | evidence в `contract_schemas.py` |
| `05-data-and-api.md` | ~100 КБ | Раздел по заголовку `##` |
| `../docs/reports/2026-10-13-readiness-audit.md` | ~190 КБ, ~1 100 строк | `rg` по ID замечания |
| `../docs/reviews/G0-r1-journal.md` | ~360 КБ, ~1 200 строк | Сводная таблица в начале, `rg` по ID кластера |
| `manifest.json`, ZIP в корне | — | Нужны только для проверки целостности |

Выборки из контрактов (запускать из корня проекта):

```bash
jq -r '.paths | to_entries[] | .key as $p | .value | to_entries[] | "\(.key|ascii_upcase) \($p) \(.value.operationId)"' development-package/specs/openapi.json
```

```bash
jq '.components.schemas.Finding' development-package/specs/openapi.json
```

```bash
jq -c '.allOf[] | select(.then.properties.evidence) | {check: .if.properties.checkId.const, fields: (.then.properties.evidence.properties | keys)}' development-package/specs/observation.schema.json
```

```bash
jq -r '.invariants[] | "\(.id) \(.phase) \(.rule)"' development-package/specs/invariants.json
```
