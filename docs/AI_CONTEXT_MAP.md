Типовые задачи и минимальный набор файлов для каждой. Состояние на 2026-10-13, пакет v0.1.0. Пути даны от `development-package/`, если не указано иное. Правила работы — в [AGENTS.md](../AGENTS.md); стадии, гейты и статус — в [WORKFLOW.md](WORKFLOW.md).

## Задачи

### Продукт, этапы, объём

`README.md` → «Приоритет документов», затем `01`. Решения и риски — `08`.

### Изменить или добавить Windows-проверку

- Читать: `03` → «Семантика результата», «Проверки Windows»; в генераторе `checks`, `evidence`, `synthetic_evidence`.
- Обновить вместе: строку проверки в таблице `03` (сборка ищет `| WIN-xxx |`); оценку и переходы — `05` → «Состояния проблем»; приёмку — `07` (AT-03, AT-05).
- Если меняется число проверок — см. «Инварианты сборки».

### Проверки Microsoft 365 и права Graph

- Читать: `03` → «Проверки Microsoft 365», «Возможности интеграции»; `04` → «Разрешения интеграций»; `02` → «Выполнение облачной проверки».
- Обновить вместе: `10-sources.md` (ссылки и дата сверки); `08` (ADR-06, ADR-10, R-06); `07` (SP-03, AT-09…11, AT-15).
- P2-операций в OpenAPI нет; M365-проверки есть только в каталоге (`checks` в генераторе).

### Пакет агента и evidence

- Читать: `05` → «API агента» (лимиты, idempotency, sequence, время); в генераторе `evidence`, `observation`, `batch`, `sample`, `unavailable`.
- Обновить вместе: отрицательные примеры `bad_examples` в `build_package.py`.

### HTTP API агента или портала

- Читать: `05` → «API агента», «API портала»; в генераторе `schemas`, `security`, `operation()`, `paths`, `READ_ROLES`, `MANAGE_ROLES`.
- Обновить вместе: роли — `04` → «Вход в портал и роли»; проверки security, CSRF и mTLS-хоста — блок после `api = read_json` в `build_package.py`.
- Сам `openapi.json` смотреть через `jq` (команды в конце).

### Состояния проблем, история, отчёт, покрытие

`05` → «Состояния проблем», «Отчёт и покрытие»; `03` → «Семантика результата»; `07` → AT-05…08.

### Регистрация агента, сертификаты, mTLS, отзыв

`04` → «Регистрация и сертификаты агента»; `05` → «API агента»; `07` → SP-02, AT-02, AT-17; `08` → ADR-05.

### Изоляция клиентов, роли, RLS, аудит

`02` → «Разделение клиентов»; `04` → «Вход в портал и роли», «Угрозы и проверяемые меры»; `05` → «Сущности и ограничения»; `07` → SP-04, AT-01.

### Персональные данные и сроки хранения

`04` → «Минимизация данных»; `06` → «Восстановление и удаление»; `01` → «Границы обещаний».

### Azure, выпуск агента, эксплуатация, расходы

`06`; `08` → ADR-04, ADR-05, ADR-07; `07` → WP-07, AT-12…14.

### План, трудоёмкость, приёмка

`07`. Связь FR → AT — таблица в `01` → «Функциональные требования».

### Независимое ревью

Порядок запуска — [WORKFLOW.md](WORKFLOW.md) → «Ревью G0» и «Реестр сессий ревьюеров»: рецензенты стартуют и возобновляются только через `reviewer-cli` на снимках пакета. Текст README («Передача на независимую оценку») и вводный абзац `09` о загрузке `REVIEW-BUNDLE.md` или ZIP — часть пакета v0.1.0, а не порядок запуска. Сам запрос рецензентам — `09` → «Текст запроса»; `REVIEW-BUNDLE.md` и ZIP самим читать не нужно.

### Выпуск новой версии пакета

Номер версии и дата записаны в нескольких местах:

- `scripts/build_package.py`: `VERSION`, `DATE` и дата текстом в заголовке `REVIEW-BUNDLE.md` (строка «Версия {VERSION} от …»). Имя ZIP строится из `VERSION`; старый архив остаётся в корне.
- `scripts/generate_contracts.py`: `catalogVersion` и `info.version`.
- `README.md` (строка 3), `08` («ревью версии 0.1.0» в вопросах), `09` (строка 3), `10-sources.md` (дата сверки источников).
- Журнал принятых и отклонённых замечаний требует `09` → «Сопоставление ответов»; файла пока нет.

### Начало реализации P1

`02` → «Компоненты», «Структура будущего репозитория»; `07` → «Эксперименты P0», «Backlog и зависимости»; `08` → «Архитектурные решения». Кода пока нет; когда появится, добавить сюда разделы по коду.

### Готовность к разработке и замечания к 0.2.0

`reports/2026-10-13-readiness-audit.md` (путь от `docs/`) — аудит готовности пакета v0.1.0: 94 замечания с доказательствами и рекомендациями, в конце дополнение о составе Windows-лаборатории. Вердикты измерений идут в начале файла, замечания отсортированы по серьёзности, у каждого заголовок `### <ID> · <severity>`. Нужное замечание искать через `rg -n '^### C-06'`.

## Инварианты сборки

Значения зашиты в скриптах. При изменении состава пакета их нужно обновить вместе, иначе сборка упадёт или `VALIDATION.md` окажется неверным. Номера строк — на v0.1.0.

| Значение | Где | Когда менять |
| --- | --- | --- |
| 12 сообщений переписки | `build_package.py:136` | Изменилась переписка |
| 16 check IDs; каждый ID есть строкой таблицы в `03` | `build_package.py:147`, `:150` | Добавлена или удалена проверка |
| В примерах ровно все `WIN-*` из каталога | `build_package.py:151–158` | Добавлена WIN-проверка: дополнить `synthetic_evidence` |
| FR-01…13 в `01`, AT-01…17 в `07` | `build_package.py:197–202` | Изменились требования или сценарии |
| Операции агента, кроме `/enroll`: только `DeviceCertificate` и хост `agent.example.invalid`; мутации портала с `CsrfToken` | `build_package.py:176–195` | Изменились схемы security или хосты |
| Числа 16/13/17 и «Семь отрицательных вариантов» в тексте `VALIDATION.md` | `build_package.py:214–229` | Изменилось любое из чисел выше |
| `maxItems: 10` у `Configuration.activeCheckIds` | `generate_contracts.py:189` | Изменилось число WIN-проверок |

Выборки из контрактов (запускать из корня проекта):

```bash
jq -r '.paths | to_entries[] | .key as $p | .value | to_entries[] | "\(.key|ascii_upcase) \($p) \(.value.operationId)"' development-package/specs/openapi.json
jq '.components.schemas.Finding' development-package/specs/openapi.json
jq -c '.allOf[] | {check: .if.properties.checkId.const, fields: (.then.properties.evidence.properties | keys)}' development-package/specs/observation.schema.json
```
