# Общая библиотека политик и применение к клиентам

Пакет 0.3.2, собран 2026-10-17. Эта часть работает локально без Azure, M365 и Atera. Новых production-зависимостей и конфигурационных секретов нет. Гейты реального пилота не закрываются локальными тестами.

## Что доступно

В основном меню портала появился раздел **Policy templates / Policymaler / Policymalar**. Библиотека сохраняется в PostgreSQL и доступна сотрудникам из разных браузеров. Admin создаёт и редактирует, архивирует и применяет шаблоны; Technician и Reader читают содержимое и историю.

1. Открыть библиотеку → **New template**.
2. Указать имя, описание и область: Microsoft 365, Windows + серверные проверки или обе области. По умолчанию используются значения контрактной схемы.
3. При необходимости выбрать клиента и нажать копирование. Это заменяет черновик настройками его последней сохранённой политики. В шаблон попадают только переносимые поля выбранной области.
4. Развернуть нужные проверки и настроить активность, режим, окно свежести и пороги. WIN-011 остаётся обязательной; закрытые режимы и диапазоны берутся из схемы. Межполевые ограничения повторно проверяет сервер.
5. Просмотреть имя, область, состояние архива и изменения настроек. **Save template version** сохраняет только библиотеку.
6. Для изменения выбрать шаблон → **Edit template**. Новая версия требует исходный ETag. Конфликт означает, что библиотека изменилась: сначала перечитать актуальную версию, без автоматической перезаписи.
7. Для архивирования включить **Archived** и сохранить новую версию. Для восстановления включить показ архивных, открыть редактор и снять отметку. История с автором и временем сохраняется; физического удаления через API нет. В истории можно просмотреть настройки каждой версии.

## Какие данные не переносятся

Контракт `PolicyTemplateContent` принимает только `scope`, `activeCheckIds` и закрытый набор настроек `checks`.

- Нет tenant ID и настройки WIN-010, M365-007, m365.excludedUserIds, расписаний M365/агента и параметров буфера.
- Не принимаются перечни привилегированных ролей и согласий, доверенных антивирусов/межсетевых экранов, defenderApproved, разрешённых SID/RID и исключений редакций.
- Параметры клиента сохраняются при применении, включая параметры проверок вне области шаблона. Windows-область пользовательского шаблона включает SYS-*; прежний встроенный Windows-пресет остаётся отдельным вариантом без изменения SYS-*.
- Ограничение действует и на API, а не только на форму. Нельзя вставить идентификаторы в дополнительные поля JSON. Свободный текст имени/описания вводит сам Admin: туда не следует копировать секреты и идентифицирующие данные клиентов.

Схема переносимых полей задаётся `development-package/scripts/contract_policy_templates.py`; карта полей и диапазонов `policy-template-fields.g.json` генерируется `tools/contracts/gen_policy_defaults.py`, проверяется в CI и вручную не редактируется.

## Массовое применение

1. Выбрать действующий шаблон и нажать **Apply to customers**.
2. Явно отметить до 50 активных клиентов. Автоматического включения незагруженных страниц нет. Список организаций загружается существующим общим механизмом портала; для текущего масштаба он покрывает всех клиентов.
3. Нажать **Preview selected customers**. Сервер читает каждого клиента в отдельном согласованном снимке; политик, аудита и заданий ещё не создаёт.
4. Для каждой строки проверить точное сравнение before/after. `ready` — есть изменения; `unchanged` — записывать нечего; `unavailable` — клиент недоступен, неактивен или результат не проходит ограничения. Неудача одной строки не делает остальные успешными и не блокирует их просмотр.
5. Подтвердить применение к числу готовых клиентов. Каждая запись — отдельная транзакция. Просмотр истекает через 30 минут.
6. Проверить результат каждой строки. При конфликте, истечении срока или пропущенных клиентах нужен новый просмотр. Уже успешно применённые политики при новом просмотре обычно становятся unchanged, если за это время не менялись.

Просмотр связан с Admin, клиентом, версией шаблона, версией политики, хэшем результата и случайным nonce. Сервер подписывает token существующим ключом Cursors. Браузер не присылает конфигурацию для записи: сервер снова объединяет шаблон с актуальной политикой и сравнивает просмотренный результат. Смена политики или шаблона, включая архивирование, даёт 412; новый результат автоматически не подставляется.

В транзакции записи блокируется клиент; версия шаблона защищена от изменения блокировкой заголовка. Вместе сохраняются policy_revision, nextPolicyVersion, recalculate_policy, обычный аудит и квитанция. Если сохранение любой части падает, остальные изменения откатываются.

Квитанция делает повтор запроса безопасным. После потери ответа или 5xx результат показывается как **Result not confirmed**, отправка остальным клиентам останавливается. **Confirm previous result** повторяет ровно тот же token и ETag; уже завершённая операция вернёт первоначальную policyVersion и replayed=true, без новой политики, задания или аудита. Подтверждение возможно и после истечения 30 минут, если операция уже завершена и квитанция ещё хранится. Неактивный клиент остаётся защищён от изменений. После ухода со страницы новые запросы не начинаются; текущий запрос уже мог сохраниться, поэтому при возврате нужно снова посмотреть актуальные политики.

Общей транзакции и автоматического отката всей группы нет. Перед применением существенных изменений следует проверить малую группу клиентов, затем остальные. Выбор клиентов и preview не сохраняются в localStorage. Отмена не отправленных запросов не отменяет уже созданные ревизии.

## API и данные

Контракт: `development-package/05-data-and-api.md`, раздел «Общая библиотека шаблонов и применение».

| Операция | Назначение |
| --- | --- |
| listPolicyTemplates / getPolicyTemplate | Текущие версии, cursor, показ архивных |
| createPolicyTemplate / createPolicyTemplateRevision | Создание и новая версия, архивирование/восстановление |
| listPolicyTemplateRevisions | Неизменяемая история |
| previewPolicyTemplate | Явные organizationIds, If-Match шаблона; никакой записи |
| applyPolicyTemplate | Один клиент, подписанный просмотр, If-Match политики, повтор по квитанции |

Миграция `0004_policy_templates.sql` создаёт платформенные `policy_template`, `policy_template_revision` и клиентскую `policy_template_application` с FORCE RLS. Старые миграции не меняются. Для новых данных нужен обычный запуск мигратора владельцем схемы; локальный тестовый PostgreSQL применяет её автоматически. Приложению разрешены только SELECT/INSERT истории, изменение/удаление старой версии не разрешено. Библиотека хранит историю без автоматической очистки.

Квитанции содержат хэш token, ссылки на версии, время и сотрудника; конфигурации клиентов не дублируются в платформенную таблицу. Квитанции экспортируются и удаляются вместе с организацией; ссылка на policy_revision удаляется каскадом при штатном удалении самой ревизии по срокам (не менее 12 месяцев). Содержимое неизменяемой клиентской политики остаётся в обычном хранилище политик. Общая библиотека не удаляется вместе с клиентом.

Код: `Organizations/PolicyTemplate*`, `PolicyWriting.cs`; портал: `pages/policy-templates/`, `shared-policy-templates.ts`, `bulk-policy-templates.ts`. Новые инварианты — INV-202…207. Старые номера не менялись. Тесты — `PolicyTemplateTests`, соответствующие `.test.ts`/`.test.tsx` портала. Встроенные пресеты прежнего блока сохранены.

## Ограничения локального результата

- Развёртывание Azure, реальные сессии Entra, поведение планировщика/метрик в облаке и приёмка с M365/Atera здесь не выполнялись.
- Отдельный нагрузочный профиль очереди и четыре Windows smoke-теста не входят в обычный прогон на macOS.
- Итоговая сборка 0.3.2 выполнена после общего ревью со стандартными jsonschema/openapi-spec-validator и строгой проверкой манифеста. Git-тег не создавался. Актуальные общие результаты и остаточные ограничения — [протокол выпуска](../reports/2026-10-17-release-0.3.2-review.md); числа выше относятся к проверке этого блока до итогового ревью.
- Сохранение нового шаблона не имеет отдельного idempotency key: при потере ответа нужно сначала перечитать библиотеку перед повторным созданием. Массовое применение защищено постоянными квитанциями; создание новой версии защищено ETag.
