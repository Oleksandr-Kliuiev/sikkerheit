# Аудит пакета 0.3.0 после правок по второму ревью

> Происхождение. Отчёт написал субагент Claude, запущенный в сессии разработки 2026-10-15 после внесения правок по второму ревью ([2026-10-15-review-agent-ops-plan.md](2026-10-15-review-agent-ops-plan.md)). Работал с чистым контекстом, только чтение пакета. Это не внешнее и не человеческое ревью. Номера строк — по снимку до исправления находок. Все 24 находки закрыты в том же сеансе, сводка — [0.3.0-decisions.md](../reviews/0.3.0-decisions.md).

Файлы репозитория не менялись. `validate_package.py` проходит: 45 операций, 172 инварианта, 22 строки жизненного цикла. Генератор контрактов, запущенный на копии в scratchpad, даёт `specs/` и `examples/`, побайтно совпадающие с текущими.

Пакет нейтрален: идентификаторов RV-, D- и F-, ссылок на `docs/` и имён рецензентов в нём нет. `H-KEY` — собственная гипотеза пакета, она была в нём и раньше.

Пересчитано, расхождений нет:

- **HMAC-вектор** (05:102) даёт ровно `150364374d…a39bd9`.
- **`servicingEndsAt`**: все 22 значения верны, все даты — вторые вторники.
- **Суммы расходов 06**: P1 — 112–122, P2 на B1ms — 132–172, на B2s — 182–222, test — около 46 USD.
- **SYS-003**: симуляция по дням 2026–2027 при сверке через 1–13 суток даёт 0 дней unknown.
- **Трудоёмкость** и строки таблицы календаря сходятся.

## Дефекты по убыванию серьёзности

1. **[major] `sentAt` в теле пакета несовместим с идемпотентным повтором.** 05:302, 05:435, 05:373; contract_schemas.py:283. Пакет, принятый позже 5 минут после первой попытки, получает признак часов; если же агент обновляет `sentAt` при каждой попытке, меняется `payloadHash`, и повтор принятого пакета получает 409 `idempotency_conflict`. Исправление: вынести время отправки из хэша (заголовок запроса), признак часов и `batch_too_old` считать по текущей попытке.
2. **[major] Миграции через слот staging невыполнимы на test и в запасном варианте.** 06:11, 02:40, 07:44, 06:23, 06:169. У планов Basic (B1, B2) слотов нет. Исправление: процедура миграций без слота либо план test со слотом.
3. **[major, риск] Учебное восстановление может удалить файлы production.** 06:130, 06:135, 07:145. Шаг «файлы без строк удаляются» в изолированном окружении удалит действующие отчёты. Исправление: в учебном восстановлении только отчёт.
4. **[major, пробел] Знаменатель покрытия Windows нечем вычислить.** 05:555, 01:108. Истории check-in нет. Исправление: хранить присутствие устройства по суткам.
5. **[minor] Точный клон не обнаруживается порогом оповещения.** 06:95, 05:106, 04:257. Пара клонов даёт около 2 resync в сутки, порог «больше 3» не срабатывает. Исправление: повторяемость, например 2 из 3 суток.
6. **[minor] Таблица ошибок 05 не обновлена.** 05:395 — старая формулировка `batch_too_old`; 05:396 — нет условия из шага 8.
7. **[minor] Первая регистрация может ждать сутки.** 06:63–65, 04:99, 05:441. Триггер «появился файл ключа» есть только у EnrollmentBlocked; Unenrolled без ключа не определён.
8. **[minor] Вход SYS-002/003 и `lastAcceptedCompletedAt` учитывают пакеты только для истории.** 05:274, 03:450, 05:272, 05:375–376, 05:362.
9. **[minor] Разрыв номеров ревизий после restore не обработан при приёме.** 06:130, 05:357.
10. **[minor] Целевые состояния `AGENT_ACTIONS` противоречат автомату.** contract_catalog.py:74–77: `drop_batch`, `refresh_configuration`, `resync_sequence`, `renew_session` вели в Active из любого состояния.
11. **[minor] Пересчёт после сверки месяца может не создаться.** 02:106, 02:111, 05:286, 05:497: ключ периода совпадает с ежедневным заданием.
12. **[minor] Месяцы ориентиров календаря.** 07:127: начало пилота M365 по пересчёту 4,7–6,5 месяца (в тексте 4,5–6), конец раскатки 11,2–15,7 (в тексте 11,5–15,5) — зависит от того, куда отнесены отпуск и праздники.
13. **[minor] Вывод устройства из учёта через 90 суток не определён.** 05:93, 05:214–218: нет задания и причины события, не сказано о томах.
14. **[minor] Роли в 04 не знают новых операций Admin** (`resolveDeviceIdentity`, `importWindowsReleases`, `verifyWindowsReleaseMonth`).
15. **[minor] Чтение всех организаций описано по-разному** в 04:156 и ADR-12 и в 02:123.
16. **[minor] Определение `source_change` не покрывает события SYS-003** от сверки месяца (05:199).
17. **[minor] 04:182 «итог только строже»** неверно для незакоммиченной отмены удаления.
18. **[minor] 03:472 «у сборок без него (1809 и старше)».** `DisplayVersion` появился в 20H2, поэтому верно «2004 и старше».
19. **[minor] 04:101** не называет все случаи использования ключа регистрации (замена ключа устройства, регистрация из Suspended и IdentityConflict).
20. **[minor] Описание `agentCheckIn`** (contract_paths.py:160) не называет IdentityConflict.
21. **[minor] 02:85 «буфер — не больше 100 МБ и 7 суток»** противоречит настраиваемому `maxBufferDays`.
22. **[minor] Асинхронный импорт без задания:** `importWindowsReleases` отвечает 202, а задания импорта нет.
23. **[minor] Недоверенные строки (04:237–239)** не включают `firewallProducts[].provider`.
24. **[minor] Runbooks без доступа к телеметрии:** RB-08 и RB-12 опираются на телеметрию check-in, которой нет в API.
