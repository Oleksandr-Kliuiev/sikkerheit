## Дополнение 2026-10-13: Windows Sandbox и состав лаборатории (к SP-01, A-6, B-12)

Источник: документация Microsoft Learn о Windows Sandbox (overview, обновлено 2026-10-08; install, 2026-03-31; FAQ; configuration), статья KB Parallels 116239.

Подтверждено документацией:
- Нужен Windows-хост Pro, Enterprise или Education (Home не поддерживается), AMD64 или Arm64, включённая виртуализация; внутри VM — nested virtualization.
- Гость всегда той же сборки, что хост («same build as your host OS»): разные версии, редакции и языки ОС в нём не получить.
- Песочница одноразовая: после закрытия всё удаляется. Перезагрузка изнутри сохраняет состояние начиная с Windows 11 22H2.
- Одновременно работает только один экземпляр.
- Компоненты Windows, включаемые через «Turn Windows Features On or Off», внутри не поддерживаются.
- В параметрах конфигурации .wsb нет vTPM, только vGPU, сеть, общие папки, команда при входе, аудио/видео, protected client, принтер, буфер обмена, память.
- На Apple Silicon Parallels не поддерживает nested virtualization для Windows VM (KB 116239; ответ Parallels в январе 2026 — «в разработке»). Значит, на этом Mac Windows Sandbox не запустить.

Не подтверждено первичными источниками (проверить на месте): работает ли внутри Defender и Windows Security Center, как ведёт себя Windows Update. Сторонние источники противоречат друг другу.

Вывод для SP-01:
- Windows Sandbox годится для быстрых smoke-тестов WP-04/WP-07: установка и удаление MSI на чистой системе, запуск служб, ACL named pipe и каталогов, SQLite-буфер, регистрация агента на тестовом сервере.
- Для проверки реальных состояний он не годится: WIN-002 (BitLocker без TPM), WIN-003/004/006 (Defender, WSC, Update — не репрезентативны), WIN-009/010 (Secure Boot, join). Матрицу совместимости и разные языки ОС на нём не построить.

Предлагаемый минимальный состав лаборатории (требует решения владельца, см. A-6 и вопрос 1 из 08):
1. Один Windows 11 Pro x64 хост с Hyper-V: Windows Sandbox для smoke-тестов плюс VM 2-го поколения с vTPM и Secure Boot — разные редакции и версии (25H2; 24H2 Home/Pro вне поддержки с 13.10.2026), другой язык ОС, VM со сторонним антивирусом; снимки для отката.
2. Хотя бы одна физическая машина с TPM 2.0 для финальной проверки BitLocker и Defender.
3. Возможная альтернатива части VM — Azure VM с Trusted Launch (vTPM, Secure Boot); лицензирование клиентских образов Windows 11 проверить отдельно.
4. Windows runner в CI нужен для сборки и unit-тестов, лабораторию он не заменяет.

Предложение в журнал 0.2.0: в 07 у SP-01 указать состав лаборатории, роль Windows Sandbox (только smoke) и то, какие WIN-проверки требуют физического TPM или полноценной VM.

### Виртуальные машины и Windows Sandbox вместе (предварительно)

Схема предварительная: она будет меняться после ответов владельца (вопросы 1–2 и 7 из 08), выбора ресурсов и результатов SP-01. Окончательный состав лаборатории фиксируется в 0.2.0 или по итогам P0.

- Windows Sandbox внутри VM требует вложенной виртуализации. Работает на x64-хосте с Windows и Hyper-V (`Set-VMProcessor -VMName <VM> -ExposeVirtualizationExtensions $true`, по документации Microsoft) и в VMware Workstation или ESXi на x64 с пробросом аппаратной виртуализации.
- Azure VM: вложенную виртуализацию поддерживают не все размеры; совместимость с Trusted Launch (vTPM) не проверена — уточнить до выбора размера.
- Mac на Apple Silicon: Parallels не поддерживает вложенную виртуализацию для Windows (KB 116239), поэтому песочница в VM не запустится. VM с Windows 11 ARM64 годится для ранней отладки сборщиков, служб и ACL. Для приёмки и матрицы совместимости она не подходит: P1 рассчитан на x64. Parallels на машине не установлен.

Текущий вариант:
1. На Mac — VM с Windows 11 ARM64 для повседневной отладки.
2. На ПК с Windows 11 Pro x64 и Hyper-V — VM с vTPM для SP-01 (разные версии и языки, сторонний антивирус, снимки) и Windows Sandbox для быстрых тестов MSI.
3. Одна физическая машина с TPM 2.0 — для финальной проверки BitLocker и Defender.
