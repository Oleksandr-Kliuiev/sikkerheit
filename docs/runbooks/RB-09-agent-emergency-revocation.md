# RB-09. Аварийный отзыв опасной версии агента

## Назначение

Быстро прекратить работу и установку версии агента, в которой найдена опасная уязвимость или которая подписана скомпрометированным ключом подписи (`06`, «Откат»): снять версию из утверждённых, заменить её утверждённой исправленной, поднять `minimumAgentVersion` и, при компрометации подписи, отозвать затронутые устройства.

## Владелец роли и этап

Security Owner (по умолчанию Product Owner; заместитель — Service Manager), этап P2. Выпуск исправления — Operations (RB-08).

## Признак запуска

- Уязвимость в агенте или в runtime .NET, оценённая как критическая (RB-08, шаг 7).
- Подозрение на компрометацию доступа к Artifact Signing, к конвейеру подписи или на подписанный чужой MSI с нашим издателем (находка скрипта RMM: код 33 на ожидаемо нашем файле; сообщение Microsoft об отзыве сертификата).
- Агент ведёт себя вне поведения кода (RB-06 для общего инцидента).

## Предусловия и доступы

- Роль Admin в портале («Sikkerheit Portal (prod)») с MFA; права Contributor на `rg-sikkerheit-prod` (изменение настроек приложения); Admin RMM.
- Release notes: список утверждённых версий с SHA-256; последняя исправленная версия, если есть.

## Шаги

1. **Снять версию из утверждённых.** В release notes пометить версию и SHA-256 как отозванную (дата UTC, причина), в RMM удалить задания и MSI этой версии из библиотеки и из `agent-releases`; все ссылки SAS истекают выпуском новых с коротким сроком — старые удалить вместе с blob. Скрипт RMM больше не будет устанавливать эту версию: в заданиях закреплена только утверждённая версия и её SHA-256.
2. **Остановить раскатку и обновление на отозванную версию:** отменить все активные задания RB-08, не создавать новых кольцевых заданий этой версии.
3. **Определить масштаб.** В портале «Kunder» → клиент → «Enheter» отфильтровать «Aktiv» и сравнить «Agentversjon» с отозванной; по организациям — все клиенты с агентом:

   ```kusto
   customMetrics
   | where timestamp > ago(2d) and name == "agent.check_ins"
   | extend version = tostring(customDimensions.agentVersion), org = tostring(customDimensions.organizationId)
   | summarize devices = dcount(tostring(customDimensions.deviceId)), lastSeen = max(timestamp) by org, version
   ```

4. **Заменить на исправленную утверждённую версию.** Если есть — RB-08 по сжатому графику (K0 → K1 → K2 → остальные в тот же день). Если нет и версия опасна — переходить к шагу 5 без ожидания: безопасна ли предыдущая утверждённая — решает Security Owner.
5. **Поднять `minimumAgentVersion`** выше отозванной версии (версия ниже получает 422 `agent_version_unsupported` и переходит в `VersionBlocked`: пакеты не отправляет, check-in раз в 4 часа, буфер сохраняется). Настройка сервиса `Agents__MinimumAgentVersion` на production-слоте (приложение перезапускается, окно работ вне 01:00–05:00 Europe/Oslo, если не критично; слот-липкая, чтобы swap её не вернул):

   ```bash
   az webapp config appsettings set --resource-group rg-sikkerheit-prod --name <site> --slot-settings Agents__MinimumAgentVersion=<новая_минимальная> -o none
   ```

   ```bash
   az webapp restart --resource-group rg-sikkerheit-prod --name <site>
   ```

   Проверить `https://<prod-host>/health` (200). Минимальная версия не выше версии, которую уже можно поставить: иначе все агенты уйдут в `VersionBlocked` без возможности обновиться.
6. **Компрометация подписи:** (а) отозвать/пересоздать профиль подписи Artifact Signing по инструкции Microsoft и отозвать сертификат; (б) в скрипте RMM поменять закреплённый subject издателя только если изменился CN или O (короткоживущие сертификаты Artifact Signing закрепляются по subject, не по thumbprint); (в) считать все MSI, подписанные в окне компрометации, неутверждёнными, пересобрать утверждённую версию заново с новым SHA-256; (г) оценить, ставили ли чужой MSI на ПК: код 33 и 31 в журнале заданий RMM, неожиданная «Agentversjon».
7. **ПК, на которых работала отозванная версия и есть признак захвата:** «Enheter» → ПК → «Tilbakekall enheten» (`revokeDevice`, необратимо, подтвердить «Tilbakekall»), затем переустановка агента через RMM и новая регистрация (RB-11, RB-10). Без признака захвата отзыв устройств не нужен — достаточно замены версии.
8. **Оповещения:** при утечке данных или захвате ПК — RB-06 (уведомления клиентов и Datatilsynet). Сообщить техникам, что версия отозвана.

## Проверка результата

- Отозванная версия отсутствует в библиотеке RMM и в `agent-releases`; в release notes помечена; новые установки идут только на утверждённую.
- Запрос шага 3 за последние 24 часа показывает отозванную версию только как `VersionBlocked` (у них нет пакетов), затем — нулевое число активных устройств с ней.
- `minimumAgentVersion` соответствует шагу 5: проверить поведением (тестовый агент старой версии получает 422) или значением настройки: `az webapp config appsettings list --resource-group rg-sikkerheit-prod --name <site> --query "[?name=='Agents__MinimumAgentVersion']"`.
