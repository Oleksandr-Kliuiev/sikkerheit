# Sikkerheit

Сервис регулярной проверки безопасности Microsoft 365 и Windows для клиентов небольшой IT-компании (около 40 клиентов и 400 ПК): проверки Microsoft 365 через одно приложение Graph только для чтения (P1), агент Windows через RMM компании (P2); внутренний портал показывает техникам отклонения и историю, раз в неделю формируется отчёт. Разработку ведёт один разработчик с ИИ-агентами.

Состояние на 2026-10-15: кода приложения нет. В каталоге — Development Package 0.3.0: архитектура пересобрана под масштаб компании, условия G0 закрыты или перенесены; решения, итоги двух ревью 0.3.0 субагентами Claude (не внешних рецензентов) и судьба замечаний G0 — `docs/reviews/0.3.0-decisions.md`, отчёты — `docs/reports/2026-10-15-*`. 0.3.0 собран 2026-10-15 со стандартной проверкой и заморожен тегом `package-v0.3.0`; идентичность сборки — `docs/WORKFLOW.md`. Предыдущие версии заморожены: 0.2.0 (гейт G0 пройден 2026-10-13) — тег `package-v0.2.0`, v0.1.0 — тег `package-v0.1.0`. Репозиторий git, ветка `main`. Стадии, гейты и текущий статус — [docs/WORKFLOW.md](docs/WORKFLOW.md).

Перед работой прочитать [docs/AI_CONTEXT_MAP.md](docs/AI_CONTEXT_MAP.md): там типовые задачи сопоставлены с минимальным набором файлов.

## Состав корня

- `development-package/` — версионируемый пакет: документы `01`–`10`, `specs/`, `examples/`, `scripts/`.
- `sikkerheit-app-chat-transcript.md` — первоисточник идеи: переписка начальника с ChatGPT на нюнорске. Не редактировать.
- `sikkerheit-development-package-v0.1.0.zip`, `sikkerheit-development-package-v0.2.0.zip` — архивы пакета, результат сборки. Не под git: содержимое воспроизводится из коммита, а хэш архива — нет; sha256 записаны в `docs/WORKFLOW.md`.
- `AGENTS.md` — правила для всех агентов, Codex и Claude Code читают его сами. `docs/` — навигация, workflow, отчёты (`docs/reports/`) и журналы решений по ревью (`docs/reviews/`). В пакет и архив они не входят: сборка берёт только содержимое `development-package/`.
- Не создавать `CLAUDE.md`, `.claude/CLAUDE.md` или `CLAUDE.local.md` ни в проекте, ни в родительских каталогах — в том числе командой `/init`. Если такой файл есть, Claude Code перестаёт читать `AGENTS.md`, включая `~/AGENTS.md`; глобальный `~/.claude/CLAUDE.md` на это не влияет. Заметки только для Claude добавлять в этот файл. Временные worktree агентов (`.claude/worktrees/`) удаляются после слияния и в git не попадают.

## Сгенерированные файлы

Не править вручную — следующий запуск перезапишет изменения:

- `scripts/generate_contracts.py` создаёт `specs/*.json` (включая реестр инвариантов `specs/invariants.json`) и `examples/*.json`. Источники: `contract_catalog.py` (закрытые перечни: проверки, `Problem.code`, `reasonCode`, eventType × cause, роли, действия агента), `contract_schemas.py` (схемы агента, evidence, PolicyConfiguration, схемы API), `contract_paths.py` (операции OpenAPI), `invariants_data.py` (инварианты вне JSON Schema). Контракты меняются в этих модулях.
- `scripts/build_package.py` сначала вызывает `validate_package.py`, затем перезаписывает `VALIDATION.md`, `REVIEW-BUNDLE.md`, `manifest.json`, `source/boss-chat.md` (копия переписки из корня) и ZIP в корне. `validate_package.py` ничего не пишет; его части — `validate_contracts.py`, `validate_docs.py`, `validate_invariants.py`, `schema_check.py`, `doc_tables.py`.

Порядок запуска (из любого каталога):

```bash
python3 -I development-package/scripts/generate_contracts.py
```

```bash
python3 -I development-package/scripts/validate_package.py
```

```bash
python3 -I development-package/scripts/build_package.py
```

Ошибка проверки печатает `[категория] сообщение`, останавливает сборку и даёт код выхода 1; успешный запуск печатает JSON-сводку. Нейтральность пакета (правило ниже) проверяется перед выпуском версии поиском по пакету.

## Правила изменения пакета

- Версии 0.1.0, 0.2.0 и 0.3.0 заморожены тегами. Изменения пакета идут в следующую версию с новой сборкой и записью sha256 в `docs/WORKFLOW.md`. Сборку (`build_package.py`) и тег версии выполнять только по явному указанию пользователя: сборка перезаписывает `VALIDATION.md`, `REVIEW-BUNDLE.md`, `manifest.json` и создаёт ZIP. Решения P0 вносятся в следующую версию пакета к гейту G1.
- Поведение задают `01`, `03`, `04`, `05`; OpenAPI, схемы и реестр инвариантов уточняют поля, ответы и правила. Противоречие между файлами — дефект пакета. Переписка объясняет происхождение идеи, но не является спецификацией.
- Пакет нейтрален: в нём нет имён рецензентов и моделей, ID кластеров и замечаний ревью, ссылок на журналы и аудит.
- Документы пишутся на русском; идентификаторы, поля, endpoints и permissions — как в контрактах. Переписку на нюнорске не переводить и не исправлять.
- Количества вычисляются из контрактов и печатаются в `VALIDATION.md`. Литералами заданы только FR 13, AT 17, RB 14 и 12 сообщений переписки — `validate_docs.py` (`FR_COUNT, AT_COUNT, RB_COUNT, CHAT_MESSAGES`). Форматы таблиц, которые читает validate, — в карте контекста.
- `.py`-файлы не длиннее 700 строк; новые проверки — в соответствующий модуль `validate_*`.

## Проверка

- Встроенная проверка покрывает только используемое подмножество JSON Schema (`schema_check.py` падает на неподдерживаемом ключевом слове) и не заменяет стандартные валидаторы. `validate_package.py` запускает стандартную проверку, если установлены `jsonschema` и `openapi-spec-validator`. Глобально на машине их нет; для сборки 0.3.0 они ставились во временный venv в scratchpad сессии с разрешения пользователя (запуск скриптов интерпретатором этого venv). Постоянная проверка в CI — WP-01.
- Перед пересборкой оригинала можно собрать копию во временном каталоге (`development-package/` вместе с перепиской) и сравнить через `diff -rq`. Пересборка воспроизводит файлы побайтно (проверено для 0.2.0 на 2026-10-13 и для 0.3.0 на 2026-10-15); содержимое ZIP совпадает, хэш архива меняется (время файлов).

## Экономия контекста

- Не читать целиком: `REVIEW-BUNDLE.md` (повторяет весь пакет), `specs/openapi.json` (~13 600 строк), `specs/invariants.json` (~2 800 строк), `specs/observation.schema.json` (~1 100 строк), `specs/graph-observation.schema.json` (~1 000 строк). Контракт компактнее читать в модулях `scripts/contract_*.py` или выборкой через `jq`.
- Документы `01`–`10` длинные по строкам (`05` ~100 КБ, `03` ~70 КБ, `07` ~53 КБ, `04` ~41 КБ). Читать нужный раздел по заголовку `##`.
- Для поиска использовать `rg`. Функция `grep` в шелле Claude — это ugrep: шаблоны вида `.{0,80}` рядом с кириллицей превышают его лимит сложности.
